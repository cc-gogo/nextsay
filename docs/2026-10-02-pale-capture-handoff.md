# NextSay 0.2.3 — 浅色、关系关联与读取修正

## 本次范围

- 固定浅薄荷/近白配色，包括系统夜间模式、原生主题、编辑字段和悬浮窗背景；仅背景有轻微透明度，文字不透明。
- 未关联的聊天不再显示“已带入对象资料”。临时关系仍只影响本轮。
- 保存旧对象时明确选择“保存并用于当前聊天”或“仅保存资料”。关联按钮使用同一保存流程，保留正在编辑的关系和资料。
- 保存和关联在同一数据库事务中完成。页面回调检查编辑页与账号分区；保存期间防重复提交、禁止通过返回/管理重开旧资料页，取消或失败恢复操作。
- 微信图片控件提供附件位置，OCR 中落在附件内的文字被排除，保留 `[图片]`、顺序和有证据的发送方；部分滑出聊天区域的附件按可见区域裁剪。头像和普通文本控件不作为附件。
- 保留未知发送方的本地拦截，提示改成“没看清最后一条消息是你还是对方发的”，不猜测发送方、不请求 AI。
- QQ 控件读取抛普通异常时仍尝试 OCR；协程取消不触发回退。
- 读取失败诊断增加应用、失败环节和数量字段，创建/展示均使用白名单，不记录聊天原文、备注、密钥或任意异常消息。

## 已定位的原因与限制

深色来自应用自身夜间配色。关系提示此前无条件声称带入资料，而用户截图中的对象实际需要关联；仅保存关系不等于确认当前聊天身份。

用户截图里发出的界面截图被 OCR 当作多条聊天消息。本次通过附件控件位置排除内部文字，不使用图像中的内容来识别对象身份。

QQ 上报 `173d9183-d8a6-410b-9560-35ce33d9f91d` 只有 APP-CAPTURE，不能证明具体失败环节。代码确认并修复了异常跳过 OCR 的回退漏洞，但**尚未证明它是这次设备故障的根因**。需用户准备无隐私 QQ 测试页、允许查看截图和控件结构后再核对；没有读取手机聊天、调用真实 API 或输入/发送消息。

附件排除依赖微信提供的可见图片控件结构；不同版本/OEM 的真实覆盖率尚未验证。原始图片不会上传到模型，仅上传占位文字和已识别的聊天文本。此功能不修复此前已经保存到历史中的误识别文本，也不自动合并/删除对象。
