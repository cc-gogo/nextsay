# NextSay 主动刷新与候选写入交互设计

日期：2026-08-09
状态：待用户书面确认

## 目标

修复真机测试发现的两个体验问题：面板无法明确刷新到最新可见对话；候选缺少可点击反馈，写入后也没有回到聊天输入框的完整动作。

本阶段采用主动刷新。持续监听聊天变化保留为后续方案，不在本次实现。

## 上下文刷新

- 面板标题区域增加一个熟悉的刷新图标按钮，并提供“刷新上下文”无障碍说明。
- 用户点击刷新后，NextSay 才重新读取当前微信或 QQ 窗口。
- 刷新成功后清除旧候选，回到上下文预览状态，展示最新脱敏内容。
- 用户必须再次点击“生成回复”，刷新动作本身不会上传数据。
- 刷新失败时保留旧上下文并显示错误，不发送空请求。
- 被动无障碍事件仍只判断前台应用，不读取聊天文字。

## 候选操作

- 每条候选改为完整的可点击操作行，不再由可选择文字吞掉点击事件。
- 按下时显示 Android 涟漪反馈，并触发轻量触觉反馈。
- 点击候选表示用户明确授权将这段文字写入当前聊天输入框。
- NextSay 先关闭结果面板，将窗口交还聊天应用，再定位输入框。
- 优先使用已经聚焦的可编辑节点；没有焦点时，选择聊天窗口中位置最低的可编辑、非密码节点并请求焦点。
- 聚焦成功后通过 `ACTION_SET_TEXT` 写入候选，绝不寻找或点击发送按钮。
- 写入成功后显示短提示，用户仍需检查并手动发送。
- 找不到安全的输入框或写入失败时，重新展示结果并提供显式复制按钮。

## 状态与安全

- 刷新：`Preview|Results|Error -> Preview`，旧候选失效。
- 写入开始时冻结重复点击，避免同一候选被写入多次。
- 应用或聊天包发生变化时取消刷新和写入。
- 密码节点、空候选、非白名单应用继续拒绝处理。
- 不增加自动发送、后台上传、截图 OCR 或持续聊天监听。

## 验证

- JVM 测试覆盖刷新替换上下文、刷新失败保留旧上下文、旧候选失效。
- JVM 测试覆盖输入框选择：优先已聚焦节点、否则选择最下方安全编辑节点、拒绝密码节点。
- 状态测试覆盖候选单次提交和写入失败回退。
- 真机验证 QQ：新消息到达后点刷新，预览改变；点候选有按压反馈，面板收起，文字进入输入框但不发送。
- 真机验证输入法弹出后浮窗不消失，离开 QQ 后浮窗隐藏。

## 后续方案三

未来的实时更新只能在面板打开期间进行本地读取，不得自动上传。加入前需要单独评估无障碍事件频率、节流、耗电、上下文抖动和隐私提示。
