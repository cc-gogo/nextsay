# NextSay 轻量 AI 输入法设计

## 背景

QQ 会向无障碍服务暴露标准可编辑节点，因此 NextSay 可以通过 `ACTION_SET_TEXT` 写入候选。微信在荣耀 X40 上即使输入框已聚焦、搜狗键盘已经展开，无障碍树仍只有空根节点；系统输入法管理器则确认微信内部存在 `MMEditText` 和有效 `InputConnection`。因此，稳定写入微信必须使用 Android 输入法接口，不能继续依赖无障碍节点、坐标点击或模拟粘贴。

## 目标

- 新增一个真正的 Android `InputMethodService`，通过 `InputConnection.commitText()` 向当前微信或 QQ/TIM 输入框写入候选。
- 第一版只提供 AI 回复功能，不实现拼音、词库、联想、纠错或完整中英文键盘。
- 用户可通过系统输入法选择器在搜狗与 NextSay 之间切换。
- 保留当前绿色浮球与白色面板，便于兼容和对照测试。
- 点击候选只写入当前输入框，绝不触发发送。

## 非目标

- 不替代搜狗的日常中文输入能力。
- 不自动切换系统默认输入法。
- 不通过 ADB、剪贴板、坐标手势或长按菜单模拟微信写入。
- 不读取、记录或上传用户通过普通输入法键入的内容。
- 不在本阶段重写现有 OCR、历史记录或后端生成接口。

## 用户流程

### 首次启用

1. 用户从 NextSay 主界面进入系统“键盘与输入法”设置。
2. 用户手动启用 NextSay 输入法。
3. 用户在聊天输入框打开键盘后，通过系统输入法选择器选择 NextSay。

系统必须由用户明确启用和选择输入法；NextSay 不尝试绕过 Android 的输入法安全设置。

### 日常使用

1. 用户在微信、QQ、TIM 或 QQ 轻聊版中点击普通文本输入框。
2. 用户切换到 NextSay 输入法。
3. NextSay 键盘显示“读取上下文并生成”。
4. 用户点击生成后，现有无障碍服务执行一次主动捕获：QQ/TIM 使用无障碍节点优先、OCR 兜底；微信直接使用本地 OCR。
5. 现有后端返回三条候选，候选显示在 NextSay 键盘区域。
6. 用户点击一条候选，NextSay 调用当前 `InputConnection.commitText(candidate.text, 1)`，在光标位置插入文字。
7. 写入成功后清空本轮候选。用户检查内容并手动发送，或通过“切换输入法”返回搜狗继续编辑。

已有草稿不被整体替换；候选按 Android 输入法的标准行为插入当前光标位置，并替换当前选区（如果存在）。

## 架构

### `NextSayInputMethodService`

新增轻量输入法服务，负责：

- 根据 `EditorInfo.packageName` 判断当前目标应用。
- 根据 `EditorInfo.inputType` 拒绝密码及敏感文本变体。
- 渲染空闲、捕获、生成、结果和错误状态。
- 将候选提交给当前 `InputConnection`。
- 打开系统输入法选择器，供用户切回搜狗。

输入法服务不持有 OCR、数据库或网络实现。

### `ImeReplySession`

新增应用进程内共享会话，使用 `StateFlow` 发布输入法所需状态。它负责：

- 保存当前生成状态和三条候选。
- 将候选与生成时的目标包名绑定。
- 接受输入法的生成请求并转交给已连接的无障碍服务。
- 当编辑目标变化、应用包不匹配或候选成功写入时清空状态。
- 在无障碍服务销毁时注销请求处理器，避免持有失效服务引用。

共享会话只存在于应用进程内，不持久化候选或用户输入。进程退出后会话自然清空。

### `NextSayAccessibilityService`

现有无障碍服务继续拥有上下文捕获、OCR、历史合并和生成协调。它新增两项职责：

- 服务连接时向 `ImeReplySession` 注册生成请求处理器，销毁时注销。
- 将 `OverlayController` 的状态同步到共享会话。

生成请求带有目标包名。服务只有在当前活动聊天包与输入法目标包一致时才执行捕获；否则返回“当前聊天已变化”。

### 双展示面行为

- 由绿色浮球发起生成时，维持现有白色面板行为。
- 由 NextSay 输入法发起生成时，结果发布到输入法，白色面板不弹出。
- 两种入口复用同一个捕获和生成协调器，不并行发起重复请求。

## 状态与数据流

输入法状态限定为：

- `Unavailable(reason)`：无障碍服务未连接、目标应用不支持或当前输入框敏感。
- `Ready(targetPackage)`：可主动读取上下文。
- `Loading(targetPackage)`：捕获、历史合并或后端生成进行中。
- `Results(targetPackage, candidates)`：恰好三条可写入候选。
- `Error(targetPackage, message)`：可恢复失败，可重新生成。

数据流：

1. `onStartInput(EditorInfo)` 建立当前编辑目标并清空上一个编辑目标的候选。
2. 用户点击生成，输入法把当前 `targetPackage` 交给共享会话。
3. 共享会话调用无障碍服务注册的处理器。
4. 无障碍服务验证 `activePackage == targetPackage`，再执行现有 one-tap 流程。
5. 控制器状态映射成输入法状态并通过 `StateFlow` 更新键盘。
6. 用户点击候选时，输入法再次检查目标包、敏感输入状态、连接可用性和候选所属包。
7. `commitText` 返回 `true` 后清空候选；返回 `false` 时保留候选并显示错误。

## 安全与隐私边界

- 仅支持包名：`com.tencent.mm`、`com.tencent.mobileqq`、`com.tencent.tim`、`com.tencent.qqlite`。
- 密码输入、可见密码变体和 Web 密码变体全部禁用生成与写入。
- 不读取 `InputConnection` 中已有正文，不调用提取文本接口，不监听普通按键。
- 不保存候选、输入法编辑内容或密码字段信息。
- 只有用户主动点击“读取上下文并生成”时才进行 OCR、历史合并和 API 请求。
- 候选点击只调用 `commitText`；代码中不查找或点击“发送”按钮。
- 当前编辑应用与候选所属应用不一致时拒绝写入并清空旧候选。

## 错误处理

- 输入法尚未在系统中启用：主界面提供系统输入法设置入口。
- 无障碍服务未连接：键盘显示“请先开启 NextSay 无障碍服务”，生成按钮禁用。
- 当前应用不支持：键盘显示仅支持微信和 QQ/TIM，不执行捕获。
- 当前字段是密码或敏感输入：隐藏候选并禁用生成与写入。
- 当前聊天包变化：取消进行中的生成，清空候选并要求重新生成。
- OCR、历史合并或后端失败：显示现有错误信息和重试按钮，不自动降级为剪贴板粘贴。
- `currentInputConnection` 为空或 `commitText` 返回 `false`：保留候选，显示“输入框连接已失效，请重新点击聊天输入框”。
- 进程重启：会话清空，用户重新生成，不恢复旧候选。

## 界面

轻量输入法视图采用紧凑纵向布局：

- 顶部：NextSay 标识、当前状态和“切换输入法”按钮。
- 空闲态：一个主要按钮“读取上下文并生成”。
- 加载态：禁用主要按钮并显示阶段说明。
- 结果态：三条带触碰反馈的候选，每条最多显示完整多行内容。
- 错误态：错误说明和“重新生成”。

输入法视图不提供字符键盘、空格、退格或回车键。用户需要普通编辑时切回搜狗。候选写入后显示“已写入，请检查后手动发送”。

## 测试

### 自动化测试

- 输入法只接受四个支持的聊天包名。
- 密码、可见密码和 Web 密码变体均被拒绝。
- 生成请求只在无障碍服务已注册且目标包匹配时执行。
- 从微信切换到 QQ 或更换编辑目标时旧候选失效。
- 候选所属包与当前编辑包不一致时拒绝写入。
- `commitText` 成功时清空候选，失败时保留候选并进入错误状态。
- 同一时间只允许一次捕获和生成。
- 浮球入口继续渲染白色面板，输入法入口不弹白色面板。
- 现有 QQ 插入、OCR、历史和后端测试继续通过。

Android 框架交互通过薄适配器隔离，纯策略与状态流使用 JVM 单元测试；`InputMethodService` 注册、布局和资源由 lint 与 APK 构建验证。

### 荣耀 X40 真机回归

- 在系统设置中启用 NextSay 输入法并能在搜狗与 NextSay 之间往返切换。
- 微信和 QQ 分别测试生成三条候选并写入。
- 空草稿、已有草稿、移动光标、选择一段文字后写入。
- 候选写入后不自动发送。
- 微信生成后切到 QQ，旧候选不可写入。
- 密码输入框不显示候选且无法生成。
- 后端断开、无障碍服务关闭和输入连接失效时提示准确。
- 连续生成、键盘收起再展开、应用切后台再返回时无闪退。

## 完成标准

- NextSay 可作为系统输入法被用户启用和选择。
- 微信和 QQ 中点击键盘候选均通过 `InputConnection.commitText()` 稳定写入当前光标位置。
- 跨应用和敏感输入安全策略生效，候选绝不自动发送。
- 后端测试、Android JVM 单元测试、lint 和 debug APK 构建全部通过。
- 荣耀 X40 真机回归矩阵通过。
