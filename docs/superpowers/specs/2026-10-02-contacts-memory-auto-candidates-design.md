# NextSay 整合设计稿：明确操作、自动候选、对象资料与长期记忆

日期：2026-10-02，Asia/Shanghai。状态：用户已批准并要求当前会话直接实施。追加约束：开发中不反复测试，最终集中验证；不安装手机、不请求指纹、不调用真实 API；手动与自动刷新保持候选窗原位更新，不隐藏或重建窗口。

## 1. 目标与现状

目标是让 NextSay 为当前聊天对象提供更贴合关系、个人情况及过往交流的回复候选，同时减少重复点击。自动化只生成候选，不自动发送，也不自动写入微信/QQ 输入框。

用户提出的四部分统一设计：

1. 浮球的收起动作不再根据“有没有新消息”改变含义；刷新有明确按钮。
2. 长按浮球可开关自动生成候选。
3. 关系加入“恋人”，每种关系可设默认要求，每个对象可补充自己的资料与长期要求。
4. 每个对象有独立、持久的记忆档案；改备注后仍能关联原档案。

现有 0.1.6 已有本机历史基础：Room 数据库按应用包名＋规范化聊天标题区分会话，消息正文由 Android Keystore/AES-GCM 加密。合并依靠角色＋文字的顺序重叠，发送给模型的近期上下文目前限制为最近 20 条、约 3,000 字符。它还不是稳定身份的长期记忆：改名会新建会话，无重叠时不会可靠补入历史，也没有长期资料和相关旧消息检索。标题索引目前是明文，不能把现状称作全数据库加密。

本稿采用的范围：先支持亮屏、前台、当前可见的微信/QQ 单聊。不扫描后台全部聊天，不读取微信/QQ 私有数据库，不引入云端历史服务器。群聊与跨平台同人自动合并不在第一版范围内。

## 2. 浮球与候选窗

### 2.1 手动模式

- 小窗已展开：单击浮球固定收起；不检查新消息、不调用模型。
- 小窗已收起：单击浮球展开并请求当前回复。这是用户明确触发的一次生成。
- 小窗内将“生成”改为“生成新回复”：重新读取当前对话、确认对象和轮次，再生成。
- 复制后保留小窗。读取/生成期间可以点浮球取消并收起，迟到结果不能重开窗口。
- 小窗编辑要求仍采用现有独立模态编辑窗，完成/取消退出；候选窗不抢聊天输入焦点。

### 2.2 自动模式

- 浮球单击只展开/收起。已有候选直接展示，不因为展开又调用一次 API。
- 无候选时显示“等待新消息”或当前任务状态；仍可主动点“生成新回复”。
- 新结果生成后，展开的小窗就地更新；收起的小窗保持收起，浮球显示一个小点提醒。打开后清除提醒。
- 候选明确标注所属对象及“当前/上轮”状态；新消息处理中，旧候选不能伪装成最新回复。

两种模式的共同原则：小窗展开时，浮球永远是收起入口；“生成新回复”永远是主动刷新入口。不使用双击刷新，长按固定进入菜单。

### 2.3 长按菜单

菜单显示当前对象与关系，并包含：

- 自动生成候选：当前对象的开关，默认关闭，记住用户选择。
- 关系与偏好：选择关系，编辑该关系的共用默认要求。
- 补充对象细节：当前对象的资料与长期回复要求。
- 记忆档案：查看、修正、删除该对象的记忆，关联已有对象。
- 详细面板：保留原长按可达的详细功能。

开关按对象生效，避免给某个朋友开启后，让客户聊天也自动上传。主应用另提供“总暂停”，能一次暂停所有对象的自动生成；解除总暂停恢复原有对象开关，不批量处理错过的消息。

## 3. 关系、对象详情与本轮要求

关系：未指定、领导、老师、客户、同事、朋友、家人、恋人。关系只是风格提示，不代表自动承诺、编造亲密程度或替用户做决定。

三类要求必须分开保存和显示：

| 内容 | 作用范围 | 生命周期 |
|---|---|---|
| 关系默认要求 | 同类关系，例如所有“朋友”档案的基础风格 | 持久，可编辑；修改时提示影响范围 |
| 对象详情与长期要求 | 当前这个人，例如某个朋友的情况、称呼与禁忌 | 持久，不随新消息清空 |
| 本轮补充要求 | 当前回复，例如“至少 50 字” | 同轮改写/重试保留，新一轮清空 |

“补充对象细节”可填写：常用称呼、相处背景、已知兴趣或情况、交流禁忌、长期回复偏好。以可选短字段和自由文本为主，不强迫填写完整个人资料。

例如：关系选“朋友”，默认要求“自然、轻松”；这个对象的长期要求“不要开他的工作玩笑”；本轮要求“安慰他，至少 50 字”。换到另一个朋友，只继承朋友共用风格，不带过去前一个人的基本资料。

表达要求冲突时，本轮明确要求优先于对象长期风格，对象长期风格优先于关系默认风格。事实与风格分开：当前聊天里的引用不是系统指令；AI 推测不能覆盖用户明确填写的事实，也不能把旧资料当成永久不变的现状。

编辑要求或对象资料时暂停自动请求，不覆盖正在输入的草稿。如果编辑期间收到新消息，退出时先提示是否将这次临时要求用于新消息；确认前不自动调用。选择用于新消息则绑定到最新轮次；不采用则新轮次清空旧临时要求。长期对象资料不受轮次清空影响。

## 4. 对象身份与改备注

### 4.1 推荐选择

三种做法的取舍：

- 只按备注建档：容易实现，但改名后档案割裂，同名对象也可能串档。
- 仅凭相似聊天内容自动合并：省确认操作，但“你好”“吃饭了吗”、转发内容和相似对话不足以证明同一个人。
- 固定对象 ID＋备注别名＋用户确认关联：本稿推荐。历史不会随名字改变而搬来搬去，疑似改名也不会直接把别人的信息合并进去。

每个对象建立不变的本机 UUID。备注、昵称是这个 ID 的别名，不是存储主键。微信与 QQ 分开建档；不同登录账号也分开。不能可靠自动识别登录账号时，由用户选择“账号空间”，不假装已经自动获得微信真实联系人 ID。

聊天标题只是查找线索。相同标题命中多个档案时必须消歧，不能取第一条记录。需要主动切换微信/QQ 登录账号时，用户也应切换 NextSay 账号空间；第一版不承诺无授权地识别所有账号切换。

### 4.2 改名关联流程

1. 当前聊天出现未绑定的新标题。
2. 在本机寻找同平台、同账号空间的可能旧档案。连续、多条、有区分度且角色顺序一致的消息重叠可作为辅助证据；简单问候、单条相似文字不作为确认依据。
3. 提示“是否将当前聊天关联到原来的某某档案？”由用户确认，或选择新建档案。
4. 确认后把新名称加入原 UUID 的别名，更新显示名；原消息、对象详情、关系和设置继续归属于同一档案。无需复制一份旧历史到新目录。
5. 无重叠时，可手动选已有档案关联。不能据此承诺任何改名都能自动识别。

身份确认前暂停自动生成，不向模型发送猜测所属对象的长期资料。用户仍可手动选择“仅按当前画面生成”，不附加任何候选旧档案的资料。备注关联时不向外部模型上传全部档案来判断身份。

如果后续有明确授权页面提供可靠微信号/QQ号，可作为更强的身份核验线索；当前 OCR 标题不是这样的稳定 ID。跨平台同一人的合并只允许用户主动确认，第一版不做自动跨平台合并。

## 5. 每个人的持久记忆

### 5.1 存储

每个人有独立的逻辑档案，包括别名、关系、资料、长期要求、已观察的消息与记忆条目。推荐沿用本机数据库，以固定对象 ID 隔离，而不是按备注建立容易改名的文件夹。独立档案不要求物理上每人一个目录；需要导出时可按对象生成独立的加密档案文件。

新资料与消息正文保存在应用私有空间并加密。别名查找建议使用本机密钥生成的 HMAC 索引，显示名加密；原有明文标题索引要随迁移处理。密钥依赖本机 Keystore，不能承诺卸载或换手机后自动恢复。覆盖更新正常保留数据库与密钥；备份/跨设备恢复需独立的可恢复加密方案，不在第一版默认开启。

保存的是 NextSay 实际识别并可靠关联到对象的聊天片段，不是微信/QQ 的完整历史导入。之前从未显示、从未识别到的消息，NextSay 不会凭空拥有。可由用户主动展示历史。

有可靠重叠时顺序合并、去重；对象已经确认但与旧历史无重叠时，保存为独立的“观察片段”，标记来源与观察时间，保留片段内部顺序，不强行接到旧历史末尾，也不拿它证明新消息刚到达。这样间隔几天后重新聊天仍能保存已看到的内容，不必为了防误合并而永远丢弃无重叠的新画面。片段间重复与先后无法确定时保留不确定标记，不用单条文字指纹全局去重，避免把不同日期的相同问候误删。对象未确认时，不把片段写入猜测的旧档案。

生成过的 AI 候选不是用户已经发出的消息，不能直接写入真实聊天记忆。只有实际聊天里观察到的消息才能按其角色保存。记录“本机观察时间”时要明确它不等于原始发送时间。

### 5.2 如何使用久远记忆

只保存文件不等于模型能记住：每次生成都需要把相关内容放进请求。

第一版组成：当前对话＋对象详情＋关系要求＋本轮要求＋相关旧消息。旧消息在本机解密后按关键词/相关性检索，只在当前对象档案内寻找，去掉与近期消息重复的片段；不为检索额外调用外部 embedding 服务。无法找到可靠相关内容时宁可不附加，不编造记忆。

保留现有近期上下文上限作为基础，为对象详情、长期要求及相关片段另设预算；请求内容整体建议约 6,000 字符上限，优先保留最新对方消息和本轮明确意图。字符预算不是模型 token 预算，具体长度需结合已配置模型验证。不会每次上传这个人的全部历史。

首版的“记忆条目”由用户明确填写/确认，可查看和删除。模型抽取的自动摘要可以作为后续可选增强，默认不做后台摘要调用；启用前提示额外 API 用量。摘要必须保留来源、时间和推测标记，可修正，不能把候选或猜测变成确定事实。

例如，用户已确认对象“最近在准备考试”，本次对方提到复习压力时可附加；不会在不相关的回复里主动复述个人资料。过期、相互冲突的信息需提示或降低使用优先级，不伪装成当前事实。

### 5.3 管理与隐私

- 每个对象可关闭长期保存、关闭使用长期记忆、删除某条记录，或删除整个档案；关闭保存不等于删除已有记录，按钮应明确区分。
- 修正/关联错误要支持解除本次关联；在没有稳定消息 ID 的情况下，不轻率承诺任意历史合并都可无损撤销。第一版的备注关联保存关联审计与原归属，不做自动实体档案合并。
- 首次开启“使用长期记忆”或自动生成，明确提示：相关聊天和所填写的资料会发送到用户配置的 API 服务，受该服务的数据政策影响；本机加密不等于从不外传。
- 不上传对象 UUID、备注索引或无关人员资料作为生成必需数据。用户明确写在资料/消息里的名字属于所选择的请求内容，不能承诺自动消除所有身份信息。
- 诊断日志不记录 API Key、聊天正文、对象详情、提示词或记忆正文。使用随机诊断编号、触发原因、阶段耗时、队列状态、轮次版本、是否使用记忆及截断/错误类型等元数据辅助调试。

## 6. 自动生成候选

仅在总暂停关闭、当前对象开关开启、身份已确认、屏幕亮着且当前聊天在前台时运行。切后台、锁屏、离开聊天、关闭开关或对象绑定不确定时暂停；不追补后台错过的消息。

开启或进入聊天先建立当前画面基线，不把已经存在的旧消息当作新到达批量调用。用户主动点击“生成新回复”始终可以请求当前内容。

自动处理规则：

1. 聊天变化事件经过过滤与约 1～2 秒防抖，再读取当前聊天。
2. 只有有足够依据的新增对方消息触发。自己发言、输入草稿、键盘变化、滚动旧记录和重复画面不独立触发。
3. 连续到来的消息合成最新一轮，去重；没有完整用户输入时，不推测未知角色为对方。
4. 新轮次清空旧的临时补充要求，保留对象资料及长期要求。
5. 同时只允许一个当前生成任务。新轮次使旧结果失效；必要时取消旧请求，旧结果不得覆盖新对象或新轮候选。取消客户端请求不保证 API 服务退费或停止计费。
6. 手动生成与排队中的同一轮自动生成协调，只发一个当前任务；显式同轮改写仍可产生新请求。保存对象资料或改变关系后，下一请求必须使用新版本。
7. 超时、限流、识别失败或角色不确定时显示状态与诊断入口，不无限自动重试。后续有明确新消息可重新尝试；同一失败轮次由用户手动重试。
8. 关闭自动开关立即取消待执行的自动任务，失效的自动结果不弹出；明确由用户触发的手动任务不因为关闭自动模式而误取消。

微信仍依赖 OCR，QQ 优先无障碍读取，必要时 OCR。OCR、消息相似、无重叠与不可靠滚动事件都可能影响检测；自动生成是尽力识别，不是官方消息回调，也不是 100% 每条实时触发。

当前为了避免闪烁，小窗打开时暂停后台 OCR。新实现必须把“变化判断、截屏、展示”解耦，以真实变化事件与冷却限制驱动，不简单取消暂停后进行持续截图。Android 13 的悬浮窗可能遮挡截图，截图隐藏/恢复方案需真机验证，不能只靠单元测试承诺完全不闪烁。通知监听属于额外权限与数据来源，本稿不默认加入。

## 7. 结构与旧数据迁移

独立职责：

- 悬浮窗交互层：固定点击含义、菜单、候选状态和模态编辑，不自行决定对象身份。
- 对象档案层：平台/账号空间/固定 ID/别名、关系与长期资料、确认关联。
- 历史与检索层：加密存储、可靠顺序合并、本机相关片段查询；候选不冒充已发送消息。
- 自动调度层：启停、防抖、去重、队列、请求版本与过期结果丢弃，不自行发送消息。
- 请求上下文层：按当前确认对象拼装有预算的资料/历史/临时要求，用显式字段隔离写作要求和引用聊天。
- API/诊断层：继续使用用户自己填写的 OpenAI 兼容 URL、API Key、模型；扩展诊断元数据而不是泄漏内容。

从现有 Room v1 迁移：保留原会话与加密消息，创建固定档案 ID 和别名映射；平台与账号空间参与隔离，旧档案的账号归属由用户确认。相同标题或疑似重复档案不自动合并。保留原排除保存设置。迁移以事务和版本验证执行，不用“清空数据库重新建”替代迁移。API 配置与浮球位置不受影响。

## 8. 建议交付顺序与验收

这是三个依赖明确的阶段，不建议同时上线所有未经验证的自动化：

1. 明确浮球操作＋长按菜单＋恋人关系＋对象详情＋固定 ID 建档和旧数据迁移。先建立可靠对象归属。
2. 持久档案管理＋本机相关历史检索＋改备注辅助关联。检验不会串人、资料重启后仍在。
3. 自动生成调度＋启停与费用提示＋新消息检测真机验证。身份与记忆已稳定后再自动上传生成。

自动摘要、跨设备加密备份、后台通知监听、跨平台合并是后续可选增强，不属于本稿首版必须交付的功能。

关键验收：

- 小窗展开时单击只收起，API 调用数为零；自动模式已有候选时展开也不重复调用。
- 手动按钮读到最新画面；新轮次清临时要求，同轮重试保留；两个对象资料不会互相带入。
- “恋人”及所有关系可选择；关系共用要求与当前对象详情的作用范围清楚，更新后生效。
- 同名对象需确认；改备注确认后 UUID 不变、旧历史可用；无法确认时不自动注入旧档案。
- 重启、覆盖更新保留档案；数据库迁移不删除现有消息；排除对象仍不保存。
- 检索只限当前档案，长期内容按预算附加，不把 AI 候选记成自己已发送的消息。
- 自动去重、连发合并、手动/自动协调、锁屏后台暂停、关开关取消、迟到结果隔离和失败无无限重试。
- 长要求、键盘焦点、复制后保留、编辑中来消息和 OCR 隐藏/恢复不回归；对重复文字/未知滚动保守处理。
