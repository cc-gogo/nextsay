# NextSay 0.2.1：简化对象资料与原生界面改版

## 用户确认的改动

- 统一绿色原生安卓界面：首页、对象列表、对象资料、模型设置、诊断页、悬浮窗。共享颜色、字号、圆角与间距；支持系统深浅色。增加绿色对话框 N 标识的启动图标。
- 对象列表不再暴露 UUID、包名、账号空间等内部信息；日常编辑保留关系标签、一个补充资料框、自动生成开关及保存。
- 一套全局 OpenAI 兼容 API 配置保持不变。没有新增每对象 API，也没有部署公网后端。
- 新建对象默认保存并使用长期记忆，自动生成默认关闭。首次进入对象管理显示数据与费用说明；确认后将旧默认关闭的 useMemory 统一开启。saveHistory=false 与旧标题排除仍保留。不同登录账号仍有独立分区，入口移至“更多管理”。
- 旧版独立的回复偏好、手填记忆在单一编辑框中带文字标题显示。未编辑时保持原字段；编辑后解析标题保留原优先级，避免长背景挤掉有效偏好。完整资料保存在本机，模型请求仍独立限长。
- 已有疑似重复对象由用户在“记忆与对象管理→合并重复对象”明确确认。事务中转移所有观察记录、别名、审计和旧版导入标记，保留资料及关系信息；如果任一对象在当前账号已确认，保留该可用身份。合并不触发 API，合并后关闭自动生成。
- OCR 标题轻微抖动只有在唯一候选、同平台同账号、已确认对象、至少三条不同且足够长的高置信度角色有序连续消息匹配时才复用身份。名字相似、短问候或低置信度不足以自动识别人；明显改备注仍需要确认。
- “选择聊天”这种旧版非聊天候选放进“更多管理→待整理记录”，未删除。其他名称不擅自删除。
- 高级悬浮面板移除原生 Spinner 下拉，改为同一窗口内的关系标签，避免另建弹窗依赖窗口令牌。候选刷新不隐藏、不移除/重新挂载窗口；等待期间旧候选保留但不可复制。仍不自动输入或发送。

## 已知边界

- 只保存前台实际识别过的文字，不等于完整微信/QQ历史。识别时间不等于原始发送时间。
- 模型只接收有预算的资料与相关记忆片段，不会每次上传整个本地档案。无显式偏好段的新单框资料以末尾最多400字补充偏好，属于有界启发式。
- 身份证据从近期最多1000条观察记录按段匹配，避免把不连续片段拼成身份；长历史的跨全库检索留待后续扩展。
- OCR 无法读到悬浮窗遮住的文字；当前坚持不隐藏悬浮窗截图，可能保守漏检，不以错误归属换取自动触发。
- 真实装机可能要求用户指纹，必须手动验证；不能绕过。
